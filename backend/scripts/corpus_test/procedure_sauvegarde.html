Procédure de sauvegarde et de restauration

Document de test fictif, rédigé pour valider le RAG navigation. Cellule Infrastructure (I1), version 1.0 du 10 octobre 2026.

1. Objet

Cette procédure décrit comment les données de GANDAL sont sauvegardées, combien de temps les sauvegardes sont conservées et comment restaurer une machine virtuelle ou un fichier. Elle s'adresse aux membres de la cellule Infrastructure et aux administrateurs des autres cellules.

2. Périmètre

Sont sauvegardés : toutes les machines virtuelles du cluster NOVA, la configuration du pare-feu GARDIEN et le partage /mnt/projets de SIRIUS. Les sauvegardes des machines virtuelles et de la configuration sont stockées sur le serveur ARCHIVE (Proxmox Backup Server, adresse 10.10.40.30, interface web sur le port 8007), dans le datastore vm-backup.

Le nœud GPU REM n'est pas sauvegardé en entier : seuls ses fichiers de configuration le sont. Les modèles et les jeux de données doivent être rangés sur le partage /mnt/projets de SIRIUS, qui est protégé par des instantanés.

Une sauvegarde qui échoue déclenche une alerte critique dans la supervision. La cellule Infrastructure doit relancer la sauvegarde le jour même.

4. Durée de conservation

Les sauvegardes des machines virtuelles suivent la règle de rétention suivante : 7 sauvegardes quotidiennes, 4 sauvegardes hebdomadaires et 6 sauvegardes mensuelles. Une machine virtuelle peut donc être restaurée dans l'état où elle se trouvait jusqu'à six mois en arrière.

Les instantanés ZFS de SIRIUS sont conservés 14 jours. Le nettoyage des anciennes sauvegardes (prune puis garbage collection) s'exécute chaque samedi à 05 h 00 sur ARCHIVE.

5. Restaurer une machine virtuelle

  1. Se connecter à l'interface Proxmox du cluster, https://nova.gandal.lan:8006, avec un compte administrateur.
  2. Dans l'arborescence, ouvrir le stockage ARCHIVE puis l'onglet Backups.
  3. Choisir la sauvegarde de la machine à la date voulue et cliquer sur Restore.
  4. Indiquer un nouvel identifiant de machine virtuelle, dans la plage 900 à 999, pour ne pas écraser la machine d'origine.
  5. Démarrer la machine restaurée, vérifier son contenu, puis seulement l'échanger avec la machine d'origine.

En ligne de commande, la même opération se fait sur un nœud NOVA avec la commande qmrestore suivie du chemin de la sauvegarde et du nouvel identifiant.

6. Restaurer un fichier

Pour récupérer un seul fichier sans restaurer toute la machine, ouvrir l'interface web d'ARCHIVE sur le port 8007, sélectionner la sauvegarde, puis utiliser le bouton File Restore. Le fichier peut être téléchargé directement depuis le navigateur.

Pour un fichier du partage /mnt/projets, il suffit de parcourir le dossier caché .zfs/snapshot du partage, qui contient les instantanés des 14 derniers jours.

7. Tests de restauration

Le premier lundi de chaque mois, la cellule Infrastructure restaure une machine virtuelle tirée au sort dans la plage d'identifiants 900 à 999, vérifie qu'elle démarre et que ses données sont lisibles, puis la supprime. Le résultat est consigné dans le registre des tests de restauration, sur le Drive de la cellule.

8. Contacts

Pour toute demande de restauration, ouvrir un ticket dans le projet « Infrastructure » du gestionnaire de tickets. Les demandes sont traitées sous un jour ouvré. En dehors des heures ouvrées, seule l'astreinte de la cellule Exploitation peut lancer une restauration urgente.
