Architecture générale du mini data center GANDAL

Document de test fictif, rédigé pour valider le RAG navigation. Cellule Infrastructure (I1), version 1.2 du 20 octobre 2026.

1. Objet du document

Ce document décrit l'architecture du mini data center GANDAL : les machines, leur rôle, leur place dans le réseau et les principaux flux entre les services. Il sert de référence commune aux cellules du projet.

Le plan d'adressage détaillé, les VLAN et les règles du pare-feu sont décrits dans le document « Plan d'adressage et services réseau ». Les opérations courantes sont décrites dans les documents de procédure : sauvegarde et restauration, soumission d'un job GPU, supervision et alertes.

2. Vue d'ensemble

GANDAL est installé dans la salle serveur du bâtiment B. L'ensemble tient dans deux baies de 42U. L'alimentation passe par un onduleur de 6 kVA qui assure environ 25 minutes d'autonomie à pleine charge, puis déclenche l'arrêt propre des machines.

Les machines physiques forment quatre groupes : le cluster de virtualisation NOVA, le nœud de calcul GPU REM, le serveur de stockage SIRIUS et le serveur de sauvegarde ARCHIVE. Le pare-feu GARDIEN sépare le réseau du campus du réseau interne de GANDAL. Le serveur EMILIA porte la passerelle des modèles d'IA.

2.1 Cluster de virtualisation NOVA

Le cluster NOVA réunit trois serveurs Proxmox VE 8, nommés NOVA-1, NOVA-2 et NOVA-3. Chaque serveur dispose de deux processeurs Xeon de 16 cœurs et de 256 Go de mémoire. Le stockage des machines virtuelles repose sur Ceph, avec une réplication sur trois nœuds, soit 12 To utiles.

La haute disponibilité est activée : si un nœud tombe, ses machines virtuelles redémarrent sur les deux autres en moins de trois minutes. L'interface d'administration est accessible à l'adresse https://nova.gandal.lan:8006, depuis le VLAN d'administration uniquement.

2.2 Nœud de calcul GPU REM

REM est un serveur physique équipé de deux cartes NVIDIA RTX 4090 de 24 Go, de 128 Go de mémoire et d'Ubuntu Server 24.04. Il sert les modèles de langue avec Ollama sur le port 11434 et héberge JupyterLab sur le port 8888, dans le conteneur CT310.

Les entraînements longs ne se lancent pas depuis JupyterLab : ils passent par l'ordonnanceur gandal-gpu, décrit dans la procédure de soumission d'un job GPU. REM est exploité par la cellule Calcul (C1).

2.3 Stockage SIRIUS

SIRIUS est un serveur TrueNAS SCALE équipé de huit disques de 16 To montés en RAIDZ2, soit environ 85 To utiles. Il exporte en NFS le partage /mnt/projets, monté sur les machines virtuelles, et propose des partages SMB pour les postes des utilisateurs. Des instantanés ZFS sont pris toutes les six heures.

4. Service GANDAL-AI

GANDAL-AI est l'assistant du projet. Il tourne sur la machine virtuelle VM150 et répond sur le port 8090, avec deux routes : /health pour l'état du service et /chat pour poser une question. Il est maintenu par la sous-cellule IA (AI1).

GANDAL-AI s'appuie sur un index vectoriel Qdrant installé sur la même machine, sur le port 6333, joignable uniquement en local. Pour générer ses réponses, il appelle la passerelle LiteLLM d'EMILIA sur le port 4000, qui transmet les requêtes à Ollama sur REM, port 11434.

5. Principaux flux

  • Un utilisateur se connecte d'abord au VPN WireGuard de GARDIEN (port 51820/udp), puis au BASTION sur le port 2222, d'où il rejoint les autres machines.
  • Les applications qui utilisent un modèle de langue appellent EMILIA sur le port 4000, qui relaie vers REM sur le port 11434.
  • Toutes les machines virtuelles montent le partage NFS de SIRIUS.
  • ARCHIVE sauvegarde chaque nuit les machines virtuelles du cluster NOVA.
  • VM160 collecte les métriques de toutes les machines grâce à node_exporter, sur le port 9100.
